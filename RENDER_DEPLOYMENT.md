# Deploy to Render - Quick Guide

This guide will help you deploy your POS system to Render for testing (and production).

## Prerequisites

- GitHub account
- Render account (free tier available at https://render.com)
- Your code pushed to a GitHub repository

## Deployment Steps

### 1. Push Your Code to GitHub

```bash
# Initialize git if not already done
git init

# Add all files
git add .

# Commit
git commit -m "Initial commit - Ready for Render deployment"

# Add your GitHub repository
git remote add origin https://github.com/yourusername/your-repo.git

# Push to GitHub
git push -u origin main
```

### 2. Deploy on Render

#### Option A: Using render.yaml (Recommended - One Click)

1. Go to https://render.com/dashboard
2. Click "New +" → "Blueprint"
3. Connect your GitHub repository
4. Render will automatically detect `render.yaml` and create:
   - Web Service (Django app)
   - PostgreSQL Database
5. Click "Apply" and wait for deployment (5-10 minutes)

#### Option B: Manual Setup

**Step 1: Create PostgreSQL Database**
1. Go to Render Dashboard
2. Click "New +" → "PostgreSQL"
3. Name: `pos-db`
4. Database: `pos_system`
5. User: `pos_user`
6. Plan: Free (or Starter for production)
7. Click "Create Database"
8. Copy the "Internal Database URL" (you'll need this)

**Step 2: Create Web Service**
1. Click "New +" → "Web Service"
2. Connect your GitHub repository
3. Configure:
   - **Name**: `pos-system`
   - **Runtime**: Python 3
   - **Build Command**: `./build.sh`
   - **Start Command**: `gunicorn pos_system.wsgi:application --bind 0.0.0.0:$PORT`
   - **Plan**: Free (for testing)

**Step 3: Add Environment Variables**
Click "Advanced" and add these environment variables:

| Key | Value |
|-----|-------|
| `PYTHON_VERSION` | `3.11.0` |
| `SECRET_KEY` | Click "Generate" (Render will create a secure key) |
| `DEBUG` | `False` |
| `DATABASE_URL` | Paste the Internal Database URL from Step 1 |
| `ALLOWED_HOSTS` | `your-app-name.onrender.com` (update after deployment) |

4. Click "Create Web Service"

### 3. Wait for Deployment

- First deployment takes 5-10 minutes
- Watch the logs in real-time
- Look for "Build successful" and "Deploy live"

### 4. Access Your App

Your app will be available at:
```
https://your-app-name.onrender.com
```

### 5. Create Admin User

After first deployment, you need to create an admin user:

1. Go to your Render dashboard
2. Click on your web service
3. Click "Shell" tab
4. Run these commands:

```bash
python manage.py createsuperuser
# Follow prompts to create admin user
```

Or use the management command:
```bash
python manage.py reset_admin
```

### 6. Test Your Deployment

1. Visit `https://your-app-name.onrender.com`
2. Login with your admin credentials
3. Test POS functionality
4. Check admin panel at `/admin/`

## Important Notes

### Free Tier Limitations

**Render Free Tier:**
- ✅ Perfect for testing and demos
- ✅ 750 hours/month (enough for one app)
- ⚠️ Spins down after 15 minutes of inactivity
- ⚠️ Cold start takes 30-60 seconds
- ⚠️ PostgreSQL free tier expires after 90 days

**For Production:**
- Upgrade to Starter plan ($7/month for web service)
- Upgrade database to paid plan ($7/month)
- No spin down, faster performance

### Environment Variables Explained

- **SECRET_KEY**: Django secret key (auto-generated by Render)
- **DEBUG**: Set to `False` for production
- **DATABASE_URL**: PostgreSQL connection string (auto-set if using Blueprint)
- **ALLOWED_HOSTS**: Your Render domain (e.g., `myapp.onrender.com`)
- **CORS_ALLOWED_ORIGINS**: Frontend URLs that can access your API (optional)

### Static Files

Static files (CSS, JS, images) are handled by WhiteNoise:
- Automatically collected during build
- Served efficiently without extra configuration
- Compressed for faster loading

### Media Files (User Uploads)

⚠️ **Important**: Render's filesystem is ephemeral (resets on each deploy)

For production, you need to store media files externally:
- **AWS S3** (recommended)
- **Cloudinary** (easy for images)
- **Render Disks** (persistent storage, paid feature)

For testing, media files will work but will be lost on redeploy.

## Troubleshooting

### Build Fails

**Error: "Permission denied: ./build.sh"**
```bash
# Make build.sh executable locally
chmod +x build.sh
git add build.sh
git commit -m "Make build.sh executable"
git push
```

**Error: "Module not found"**
- Check `requirements.txt` has all dependencies
- Make sure `gunicorn` is included

### App Won't Start

**Check logs:**
1. Go to Render dashboard
2. Click your web service
3. Click "Logs" tab
4. Look for error messages

**Common issues:**
- Missing environment variables
- Database connection failed
- Static files not collected

### Database Connection Issues

**Error: "could not connect to server"**
- Make sure `DATABASE_URL` is set correctly
- Use "Internal Database URL" not "External"
- Check database is running

### Static Files Not Loading

**CSS/JS not working:**
```bash
# In Render Shell, run:
python manage.py collectstatic --no-input
```

## Updating Your App

Every time you push to GitHub, Render auto-deploys:

```bash
# Make changes locally
git add .
git commit -m "Update feature X"
git push

# Render automatically:
# 1. Detects the push
# 2. Runs build.sh
# 3. Deploys new version
# 4. Takes ~2-5 minutes
```

## Custom Domain (Optional)

To use your own domain:

1. Go to your web service settings
2. Click "Custom Domain"
3. Add your domain (e.g., `pos.yourdomain.com`)
4. Update DNS records as instructed
5. Render provides free SSL certificate
